# 正式协调核心的隔离演练（2026-10-17）

`scheduler/production_session.py` 已补齐 Stock A/US 的协调顺序，但没有接入任何线上工作流。它没有 CLI、HTTP 客户端、令牌读取或默认适配器；唯一实现的适配器位于单元测试中，全部数据仅在内存里。当前 `production-dispatch.yml` 仍只调用只读预检。

## 已验证的顺序

1. 限定原始管理员手动 Run、main、第一次尝试、准确的生产协调工作流；任务只接受 A/US 和明确的业务日期。
2. 读取登记及配置，要求总开关、单任务开关和目标白名单全部允许。真实仓库配置仍全部关闭。
3. 要求准确任务、源提交、300 秒内的交易日/收盘/行情证据和无活跃运行证明；重新应用已有云端预算或 Windows 在线空闲检查。现有只读预检无法提供 `exchangeSessionVerified=true` / `marketDataReady=true`，因此不能充当生产许可。
4. 通过原有 CAS 规则保存唯一任务预约，然后重新读取，确认配置和登记完全符合预期；再次核对准备证据、路由和源提交。
5. 仅生成一次固定私有目标的派发调用：`ref=main`、确定的 `task_id`、原协调 Run ID、`force_run=false` 和准确 Runner 模式。该调用目前只连接内存测试适配器。
6. 要求返回确定的原始 Run ID，并核对真实执行元数据所需字段：仓库、工作流、事件、main、尝试次数、源提交；REST 若提供原始输入，任何已知冲突均拒绝。通过后保存绑定并重新读取确认。
7. `observe()` 每次只观察原 Run 一次，不创建定时或后台任务。队列状态不产生心跳提交；进入运行或结束时更新状态。成功停在 `awaiting_effect_verification`，失败停在 `hold`，始终不产生业务核验成功或自动重试许可。

## 失败时保留证据

| 情况 | 结果 |
| --- | --- |
| 准备证据缺失、过期、日期不符、路由不可用 | 不登记、不派发 |
| 预约 CAS 冲突、响应不确定、读回不符 | 不派发 |
| 登记后源提交/路由变化或发现活跃任务 | 保留预约，不派发 |
| 派发超时、无确定 Run ID、返回元数据冲突 | 保留预约，禁止再次派发同一任务 |
| 已派发但绑定回写失败 | 不重发，交人工核对原 Run |
| 原 Run 成功 | 等待私有数据库提交与回执核验，不写 `verified` |
| 原 Run 失败、取消或超时 | `hold`，不自动补算 |

## 本轮验证

- 本地公开协调器完整回归 **201 项通过**，其中新增协调核心测试 **25 项**。这些都是隔离测试，不能当作线上生产运行。
- 使用当前私有准入和回执链模块做本地跨仓库契约检查 **10 项通过**，覆盖 A/US 的预约等待、准确绑定准入、错误 Run 拒绝、结束后的身份链连接及错误协调回执拒绝。回执输入是明确的合成样例，不是真实数据库提交证明。
- 当前私有准入/回执链原有回归 **17 项通过**。
- 生产配置、任务登记及全部工作流均未修改；没有策略执行、正式数据库写入、邮件或真实派发。

## 接入真实闭环前仍需完成

- 实现并审核实时交易会话/行情就绪证据适配器，保持准确任务和证据时效；常规日历候选与历史验收产物不能替代实时证明。
- 实现并审核受限的线上存储、唯一派发和 Run 查询适配器；明确处理已接受请求但丢失响应的人工对账方式。
- 在同一前台 Job 增加有截止时间的观察循环，并保留原 Run ID，恢复时只观察，不重新派发。
- 私有侧使用真实原 Run 和同一数据库提交回执核验；公开中心只接收获准公开的状态，不读取私有源码、账本或回执内容。当前 `verified` 写入仍由原存储规则禁止。
- 在具体任务、准确源码、基线和执行范围可审核后，再单独处理生产启用；本次没有打开总开关、任务开关或 Windows 生产白名单。

本文件说明的是协调核心准备工作的完成范围，不是上线批准，也不是一次真实生产闭环成功记录。
