# Stock 单任务运行与入账核验

## 运行入口

使用 `production-dispatch.yml` 的人工 `workflow_dispatch`：选择 `stock_a` 或 `stock_us`，日期留空时按实际时钟及已覆盖的交易所日历选择最近完成的交易日。`execute=false` 默认为只读预检；明确设为 `true` 才会进入单任务执行链。

`publication_mode=formal` 要求市场当地仍处于该交易日收盘后，并通过原策略的正式报告门槛。`theoretical_catchup` 只允许在该日期之后使用原生补算门槛推进理论持仓与账本，不会把补算认作正式报告或发出正式订单。`force_run` 始终为 false。

`production-launch.yml` 仅响应管理员对 `config/launch-request.json` 的明确主分支提交，用本仓库的 Actions 权限发起一次上述人工入口。请求必须匹配固定提交的市场、日期和模式；没有定时触发，也没有循环提交或自动重发。

## 执行与核验

1. 检查 A/US 共享账本没有活跃业务任务，指定 Windows Runner 在线、空闲且标签正确。
2. 派发私有实时就绪工作流，在隔离环境核对权威已结算持仓、完整原生计算、临时账本回放和真实行情源；不改正式数据库、不发邮件。
3. 仅接受同一私有源码、准确日期与模式、首次尝试的成功就绪 Run。最终证明步骤有效期为 300 秒，最新失败证据不能回退到旧成功。
4. 暂时开启且只开启本任务许可。先 CAS 预约并读回确认，再进行一次真实业务派发；私有任务必须等准确 Run/SHA 绑定完成后才执行。
5. 同一个公开调度 Job 每约 30 秒观察原 Run。查询不确定、写入冲突、超时或失败时暂停，不换 Run、不重跑。
6. 私有工作流将执行回执和新市场版本放在同一数据库提交，并独立核对真实远端提交、父提交、原 Run、快照与账本哈希及版本链。私有最终证明成功、原 Run 整体成功后，公开登记才可进入 `verified`。
7. 正常、失败和中断清理均尝试仅关闭本协调者的临时许可；默认配置保持关闭，已核验历史任务继续防重。同一日期已登记的任务不会自动重新派发。

`verified` 的补算记录证明真实数据效果；其 `formalReportVerified` 仍为 false。公开仓库只保存任务日期、模式、Run/SHA、状态及核验布尔值，不保存私有源码、持仓、净值、账本或完整私有日志。

## 失败处理

就绪失败发生在生产预约与业务派发之前，修复明确原因后可以发起新的受控请求。业务派发响应未知、任务已经预约、私有执行失败或已发生写入时，必须先核对原 Run 和实际数据效果，不删除登记或盲目重算。

仅当人工独立核实原 Run 已结束，策略、发布、配置与缓存保存步骤全部跳过，远端数据库提交与失败前完全相同，且目标日期回执不存在时，才可将原始 `hold` 记录及上述证据原子归档至 `state/prebusiness-attempts.json`，再发起新的明确请求。原 Run 和失败结论保留，不改为成功，不复用或重绑旧协调者。此为人工审计恢复，没有自动清除 `hold` 或自动重试代码。

普通配置全关不影响检查历史 `verified` 记录。当前 CLI 没有自动恢复旧协调者的写入身份；另一个人工 Run 不得冒用旧协调者继续派发。

### 已计算原提交的发布恢复

如果策略与快照校验成功，但发布确认失败，不能使用上述“业务前失败”归档例外，更不能新建业务任务重算。本次 US 恢复使用独立私有工作流，无检出或工作区清理，逐项核验原失败运行、公开暂停记录、原数据库父提交、同一提交内的原回执及哈希链，然后只发布该原提交一次并独立读回。持仓输入与原计算缓存同步后，恢复 Run 必须整体成功并具有最后证明步骤。

人工核验使用纯函数 `scheduler.production_recovery.reconcile` 生成待提交状态；该模块没有网络、派发或自动重试能力。根任务身份、原 Run、原源码和原协调者均保留，新增 `completionMode=recovered_original_commit`、`completionRunId`、`completionSourceSha`。普通状态存储仍禁止把 `hold` 改成 `verified`。恢复证明和实际远端数据再次独立核验后才人工 CAS 提交状态。

本次一次性 push 恢复触发器已移除，遗留启动请求已关闭。参见[真实验收记录](production-acceptance-20261017.md)。

## 额度和范围

两个个人账户的配置免费额度均为每月 2000 分钟。公开仓库的标准托管运行器用量排除在私有免费额度消耗之外；无法核实的余额保持未知。不能因余额查询失败而判定额度耗尽，也不能绕过云端预算门。Windows 自托管路径仍需要完整的 Runner、源码、日期、准入和回执验证。

此入口仅支持已接线的 A/US 单任务。ETF、Android 私有签名和公开正式发布不因本次接线而自动开启。

协调器本地 243 项回归覆盖请求来源、单次派发、许可恢复、原 Run 监控、明确原提交恢复，以及真实证明缺失时的拒绝行为；真实运行结果另列于验收记录，不能用这些测试代替实际入账。
